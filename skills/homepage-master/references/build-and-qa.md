# 제작과 검수

## 제작 기준

- **구성**: 기존 프로젝트의 방식을 따른다. 새로 만들면 정적 HTML, CSS, 약간의 스크립트로 충분하다.
- **색과 크기**: CSS 변수로 정의한다.
- **반응형**: 390, 768, 1024, 1360 폭에서 확인한다. 320에서도 가로로 넘치지 않아야 한다. 누르는 요소는 44px 이상.
- **이미지**: 가로·세로 크기와 설명 글을 적는다. 첫 화면 밖의 이미지는 늦게 불러온다. 용량을 줄인다.
- **접근성**: 제목 단계 순서, 키보드 초점 표시, 글자 대비, 폼 라벨, 움직임 줄이기 설정.
- **메타**: 제목, 설명, 공유용 제목·설명·이미지, 파비콘. 도메인이 정해지기 전에는 대표 주소를 적지 않는다.
- **폼**: 필수 항목 검사, 오류는 해당 칸 아래에, 전송 중 중복 제출 방지, 실패 안내.
- **외부 자원**: 글꼴·영상·지도는 필요한 때만 불러온다.
- **파일 이름**: 영문 소문자와 하이픈. 인쇄물·QR이 가리키는 기존 경로는 유지한다.

## 검수 점검표

만든 뒤 브라우저로 열어 하나씩 확인한다. 확인하지 못한 항목은 보고에 "확인 못 함"으로 적는다.

화면
- [ ] PC·태블릿·휴대폰 폭에서 화면을 찍어 직접 봤다
- [ ] 가로 넘침이 없다
- [ ] 깨진 이미지, 콘솔 오류, 불러오기 실패가 없다
- [ ] 밝은·어두운 버전이 모두 정상이다

동작
- [ ] 메뉴, 버튼, 내부 링크가 맞는 곳으로 간다
- [ ] 필터·탭·슬라이드가 동작하고 개수 표시가 맞다
- [ ] 폼의 검사와 전송 흐름을 눌러 봤다

내용
- [ ] 자리 표시 문구, 예시 후기, 가짜 수치가 없다
- [ ] 수치·자격·실적이 출처와 일치한다
- [ ] 연도, 주소, 연락처가 최신 자료와 같다
- [ ] 오탈자와 표기 통일

브랜드와 권리
- [ ] 로고가 원본 색 그대로다
- [ ] 얼굴·이름·내부 자료가 노출되지 않는다
- [ ] 레퍼런스의 문구·이미지를 가져오지 않았다

## 다른 눈으로 보기

큰 작업은 만든 사람이 아닌 검토자에게 화면과 요청 내용만 주고 본다. 코드를 보여 주지 않아야 방문자의 눈으로 본다. 검토자가 지적한 것은 고치거나, 고치지 않는 이유를 적는다.

## 인계

- 폴더 구성과 각 파일의 역할
- 배포 방법(폴더째 올리는 방식이면 그 절차)
- 문의가 접수되는 곳과 확인 방법
- 사진·문구·자격 상태를 바꾸는 위치
- 남은 일과 받아야 할 자료
